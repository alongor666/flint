## 原文

> chexian-api前端，聚焦卡片支持拉宽，动态拉宽，可占占50%的屏幕。打开时导航栏自动关闭

## 澄清（AUQ）

- Q1 「可占 50% 屏幕」拉宽机制 选项: A（推荐）拖调上限动态化——上限=min(50% 视口宽, 帧宽−720 主区最小保护)，仍用既有拖调手柄，不加按钮 / B 一键拉宽按钮直达 50%、拖调上限维持 560 / C 两者都要 → **owner 答: A**
- Q2 开卡自动收导航后、关卡导航栏行为 选项: A 关卡自动恢复（临时收起不写偏好存储）/ B 不自动恢复——收起后保持，用户点顶栏展开钮自行恢复 / C 仅面板宽超出可用空间时才收 → **owner 答: B**

先探可定字段（依据声明）：落点=壳层单点——020 已把九处聚焦卡统一进 WorkbenchAuxiliary 壳，壳一处改全站生效，范围非分叉；50% 基准取视口宽（「屏幕」字面义，且 Q2 收导航后帧宽与视口宽差即 184px 侧栏，取视口更稳定）。

**A · 拉宽能力（原文＋Q1A）**

1. 全站聚焦卡（九处，经壳层单点生效）拖调上限动态化：**最大可拉到视口宽的 50%**（Q1A 选项原文「上限=min(50% 视口宽, 帧宽−720 主区最小保护)」——50% 基准=视口宽随裁定一并确认）。
2. 交互形态不变：**仍用既有拖调手柄**（鼠标拖拽＋键盘方向键），不加新按钮、不加预设档位（Q1A「不加按钮」）。
3. 「可占 50%」= **可拉到的上限**，非打开即占：打开时缺省宽仍 360、下限仍 320，**开卡不自动拉宽**（推导：「可」字义＋Q1A 为上限语义）。
4. 主区 ≥720px 最小宽保护与既有窄窗降级三态（side/bottom/full＋modal）行为全部不变（Q1A 选项内含「主区最小保护」；降级体系无变更理由）。
5. 560 固定上限退役；宽度偏好 localStorage **按登录身份（preferenceOwner=username）持久化——单用户一个宽度、跨路由共享**的机制不变（既有行为照旧，WorkbenchAuxiliary.tsx:9/:514；非按页隔离）。

**B · 开卡自动收导航（原文＋Q2B）**

6. 聚焦卡**每次从关到开**（面板 visible 上升沿），左侧主导航栏（SidebarLayout 184px 侧栏——非顶栏）自动收起（原文「打开时导航栏自动关闭」）；已收起时无动作（幂等）；面板开着切换工具不触发（非「打开」事件）。
7. 收起为**持久动作**（写 sidebar-collapsed 偏好存储）：关闭聚焦卡后导航**保持收起、不自动恢复**，用户点顶栏展开钮自行恢复（Q2B 选项原文）。
8. 收起之后导航的展开/保持归用户自行管理；下一次开卡事件再次触发收起（与 6 一致）；既有「落地复位」强制展开语义照旧生效（Q2B「保持收起，用户自行恢复」字面义）。
9. 仅桌面内联侧栏（≥1024）动作；抽屉视口（<1024）无内联侧栏——不收、**不写偏好**（推导：无对象可收，写偏好会污染回桌面后的体验）。
10. 收起释放的 184px 归还工作台帧（主区＋辅助区共享），拖调可拉范围随之自然扩大（机制自然结果，无额外动作）。

**C · 交付边界（防不满意条款）**

11. 九处聚焦卡行为一致（壳层单点实现，不允许某页例外）。
12. 既有能力零回归：拖调取消复原、宽度偏好记忆、窄窗三态降级、焦点归还、重开锁（＝020 建立的聚焦卡重开状态回归测试锁：专项 2＋页内嵌 5，登记见目标仓《聚焦卡规范与资产清单.md》）行为全部保持。
13. 行为变化披露进 PR 正文（三则，与探索 #1 披露清单同源）：①ov2 进页自动展开异常列表＝进页即收导航；②关卡后导航保持收起、落地复位仍强制展开；③1024–1231 视口 bottom→side 翻转。刷新后宽度/收起偏好保持属既有持久化语义，入验收项核对。

### 实施要点 · 刀面 1：拖调上限动态化（WorkbenchAuxiliary.tsx）

- 现状锚【事实】：`:231` size state＋`:278-290` ResizeObserver 观察 **frame**（size=帧宽，非视口）；`:314` actualWidth `= min(width, max(320, 帧宽−728))`——**只有帧帽、无 MAX 帽**（今日 stored≤560 故无感，动态帽后必补）；`:361` 拖调钳位含 MAX；`:394` aria-valuemax 同源。
- 改法：`effectiveMax = max(320, min(视口宽×50%, 帧宽−728))`；落点分置——`:361/:394` 落完整帽，并**补入 `:314` 渲染钳位**（不补则 >1456 视口收导航后帧帽>50% 帽，渲染态可超 50%）；**`:12` readWidthPreference 只取视口帽成分**（其求值于 useState 初始化、彼时 size.width=0 帧帽不可得——机械落完整帽会把存量 560 钳死 320 且 width state 不重读、measure 后不恢复；只落视口帽则存量 560 保留，超帽渲染态由 `:314` 兜底）；MAX_WIDTH 常量退役。视口宽经 resize 监听 state 取（模板＝SidebarLayout.tsx:273-279 既有先例，非 RO 可得——frame⊂视口，视口变化帧必变但值本身读不到）。
- 数值感【断言·代码推理】：1440 视口开卡收导航后帧=1440 → 帽 712（≈49.4%）；1920 → 960（50% 帽生效）；1280 → 552。MIN 320／缺省 360 不动；存量偏好超新帽由 `:314` 渲染钳位兜底，无迁移面。
