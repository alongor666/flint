# 协议① · 录入即讨论（建卡 · AUQ 流程）

owner 任何时刻、任何形式丢入想法（一句话或一段话），AI 当即按本协议执行。

## 流程

1. 建 `cards/NNN-slug.md` 登记原文（原话保留不改写），状态 `clarifying`，REGISTRY 加一行；
2. **先探后问**：先榨零成本通道——原文语义、会话上下文、与现有卡查重（语义同源建议并卡）、目标仓公开可探信息（仓内文档/注册表/只读探针）——能定的字段（目标仓、类型等）直接定并在卡中声明依据；
3. 探不明的**真分叉**（目标仓归属、业务口径、范围边界）以 AUQ 结构化提问一次问完：≤4 题、每题 2-4 互斥选项、推荐项置首标注（推荐）——不抛开放式问题让 owner 打字描述；
4. owner 答案即裁定，回填卡（「澄清」段落），状态转 `discussed`，git commit。

AUQ 未答时卡停在 `clarifying`，不催办；非交互场景按保守默认继续并在卡中声明假设清单（owner 纠偏即停，不以未反对为开工前提）。owner 会尽量清晰表达，流程只兜底剩余歧义。

## 防重三律（建卡强制）

1. **建卡前必查**：先读 `REGISTRY.md` 全表（卡多时 grep slug 关键词与原文高频词），比对既有卡标题与一句话——语义同源（同一诉求重复录入）**不建新卡**，在既有卡追加「补充录入」段（原话+日期），并告知 owner 已并入 NNN。owner 重复提及恰是价值信号，并入时顺带升该卡优先级备注。
2. **git 即并发协调器**：commit/push 前 `git pull --rebase`；`REGISTRY.md` 同区追加冲突 = 并发录入信号，消解冲突时对两张卡补一次语义查重；编号撞号（不同文件同 NNN）后写者让号改新号。
3. **对账公式**（健康度，随手可验）：`grep -c '^| ' REGISTRY.md` 减去表头两行 = `ls cards/*.md | wc -l`——不等即有孤儿卡或索引漏登，当场修。

## 卡生命周期

- 文件：`cards/NNN-slug.md`，NNN 三位递增全局唯一，slug 短横线英文小写。
- 状态：`clarifying`（已录入，AUQ 待答）→ `discussed`（已澄清+初评）→ `scouted`（已探索，随时可转正）→ `building`（已下令开工）→ `shipped`（目标仓 PR 已合并）｜ `dropped`（放弃）。
- 未确认的卡停在 clarifying / discussed 长期躺平是常态，不催办、不清理。
- 探索可多轮追加，旧段落保留（历史即审计）。

## 公开仓红线（建卡时强制）

本仓公开。卡内禁录：生产地址、凭据、token、内部敏感数据、目标仓代码大段原文（引文件路径+行号即可，说明性片段 ≤10 行）。业务数字按必要最小化。
