# 协议② · 确认即探索（转正前探索）

owner 对某张 `discussed` 卡表态确认（"这个方向对" / "确认" / 点名卡号），AI 马上按本协议探索目标仓。

## 动作

- **先读目标仓根 AGENTS.md 及其知识指针**（拓扑/环境/数据知识页），已知事实直接引用不重探；
- `git fetch origin`，读最新默认分支，grep 既有实现与相关文档；
- 查目标仓开放 PR / issue / 规划文档，防撞车防重复；
- 探索结果以「探索」段落追加进卡，写到 **PR 实施方案深度**：涉及文件:行号、改动面、关联口径与裁定、风险、验收命令、探查锚（仓 @ short-SHA + 日期）。

不建分支、不写代码、不动目标仓任何东西。

## 证据纪律（探索与讨论通用）

1. **证据纪律**：卡内报告的数字、结论必附产生命令或代码锚；**零命中/阴性结论换法交叉验证一次**——探索里最典型的"无重复/未找到既有实现"是零命中结论，与 grep 姿势错不可区分，防撞车结论必须两法同证。
2. **事实与断言二分**：讨论/探索段落区分【事实】（附复核命令或锚，他人可直接复现）与【断言】（须独立重推导）；结论标注方法学——实测 / 静态核实 / 代码推理，禁把推理写成实测。
3. **NO CHANGE NEEDED**：探索后既有实现已满足卡内诉求时，判 NO CHANGE NEEDED 归档（dropped 注明原因），不为转正造改动。

## 粒度（卡与 issue / PR 的映射）

- 卡 = 碎片自然粒度：一条灵感一卡，录入时不预设实现规模。
- 映射在转正时定：**多卡可并一个 issue、一个 PR**；单卡大项也可拆多 PR——以目标仓纪律与实际工作量为准，不为凑数拆细。
- **目标仓自身原则不豁免、不代造例外**：如 chexian-api 的工作项住 issue 树，转正必建 issue，PR 以 Closes #N 关联完成。本仓与目标仓协议冲突时以目标仓为准。

## 不移入并禁复制

目标仓业务规则（时间口径歧义先反问等）探索时以目标仓自身 AGENTS.md/rules 为准，本仓只放指针；PR 评审纪律（无代码无评审面）；独立裁定区（owner 对卡的裁定即卡内「澄清」段落，卡即裁定记录）。
