# 010 · 续保险别组合迁移矩阵（主全→交三、交三→单交转化）＋保额变化补充

- 状态: shipped
- 目标仓: chexian-api（依据：owner 明示"这是车险 API 仓库"；数据在 PolicyFact 与定价研究固化区）
- 类型: 数据口径/研究（一次性数据提取与表格产出）
- 录入: 2026-10-19

## 原文

同事们总是反馈经济不好了，客户买保险变少了。因此，我想提取 2021 年至 2026 年 9 月的数据。

具体需求如下：
1. 核心数据口径：
客户上一年在我们公司买保险，下一年继续续保。重点统计以下转化比例：
(a) 上一年买"主险"，下一年买"交 3 次"的，占上一年买主险的比例是多少？（即转化为"交 3 次"业务的比例）
(b) 上一年买"交 3 次"，次年买"单交"的比例是多少？

2. 表格维度：
可以从客户类别、保单年度和城市这三个维度来制作这个数据表格。

3. 补充需求：
如果可能的话，还可以继续做一件事：统计险别或保额有变化的客户。这部分可以只做 2026 年 1~9 月的数据，因为我们好像历史数据只有近两年的。

那么这件事情该怎么做？这是车险 API 仓库。（语音转写补充：上一年买的是交 1，下一年买的是交 3 的，这个占到上一年买交 1 的比例是多少；上一年买交 3，下一年买单交的。）

## 澄清（AUQ）

- Q1 转化率分母口径：A 留存口径（推荐，分母=上年该组合且次年仍在我司承保的车，反映在保客户结构降档）/ B 全量口径（分母=上年该组合全部车，含次年流失，流失与降档混在一个比例里）→ **owner 答: 未答——非交互按 A 留存口径继续，同时并列披露流失数（降档与萎缩分列，两全 B 的叙事诉求）**
- Q2 保单年度口径：A 起保年度（推荐，insurance_start_date 年份，保障年度衔接自然，2021 起组合数据全量）/ B 签单年度（policy_date 年份，业绩口径）→ **owner 答: 未答——按 A 起保年度继续**
- Q3 城市维度：A 车牌归属地（推荐，plate_no 前缀，客户所在城市，与 /policy-geo/city 同口径）/ B 出单三级机构（org_level_3，业务归属非地理城市）→ **owner 答: 未答——按 A 车牌归属地继续**
- Q4 产出形态：A 一次性分析产物（推荐，SQL 直通出数+表格文件交付；数据豁免不走 PR，flint 卡 008 裁定同源）/ B 常态化 API/页面（代码实施，走目标仓 issue+PR）→ **owner 答: 未答——按 A 一次性分析产物继续**

### 先探已定字段与依据（2026-10-19 只读探针）

- 口径映射：owner 口中"主险/交1"＝`coverage_combination` 值域「主全」，"交3次"＝「交三」，"单交"＝「单交」——字段注册表值域直接对上，无需自造分类。compulsory_commercial_link 换代全量重建后 2021 起全量有值（非空率 ≥99.99%）。
- 数据边界：policy_date 与 insurance_start_date 最早均为 2021-01-01，数据日 2026-10-18——「2021 起至 2026-09」窗口成立，可产出 2021→2022 … 2025→2026 共五个年度对。
- 可行性 smoke（2024→2025，VIN 车架号年度间自匹配）：迁移矩阵直接出数，主全→交三、交三→单交均千辆级样本，两省权限内合计匹配数万 VIN。
- 城市可行性：车牌前缀晋A/K/M/L/B/J/D/C/H/E/F 全齐，城市归属可按车牌前缀映射（晋A=太原、晋B=大同、晋C=阳泉、晋D=长治、晋E=晋城、晋F=朔州、晋H=忻州、晋J=吕梁、晋K=晋中、晋L=临汾、晋M=运城）。
- 保额补充可行性：定价研究固化区（#06 险别保额清单，pricing_coverage 端点）available，但窗口 2025-01 起（约 22 个月，与 owner"历史只有近两年"感知吻合）且为「起期月×档位」聚合快照，非 VIN 级明细；PolicyFact 的 third_party_coverage（三者保额）列口径漂移不可查，driver_coverage/passenger_coverage 可查——保额变化的落地路径待探索阶段核源清单可及性。

### 非交互假设清单（owner 纠偏即停）

- 匹配主体＝车架号 VIN（客户级自然主键，RenewalTracker 同思路），非保单号。
- 一车一年多组合时按该年最高档归类（主全>交三>单交）。
- 2025→2026 年度对：2026 年数据只到 9 月，分母限定上年起保月 ≤9 月的车（其保单年度已完整走完），否则转化率被"未到期未续"系统性拉低；2021→2024 各对不受影响。
- 客户类别取上年保单的类别（基准群属性）。

### owner 裁定（2026-10-19 第二轮）

- 险别变化统计窗口：**2021 年起**（＝主迁移矩阵全窗 2021→2022 … 2025→2026，不做窗口裁剪）。
- 保额变化统计窗口：**2025 年起**（解读为：保额数据可及的最早完整年度对 2025→2026；VIN 级源清单 2025 全年覆盖待探索核实，固化区自 2025-01 连续在窗）。
- 转化率分母口径：**留存+流失并列**（留存口径主表 + 流失表分列，降档与萎缩分两张表）。
- 省份范围：**两省分列**（山西/四川各一套表）。⚠ 技术核实点：本轮探针（SQL 直通）实测只返回晋牌数据，说明直通通道默认锁定 defaultBranch=SX——SC 侧取数通道（branch 切换/直通省域控制）在探索阶段核实。
- 续保衔接判定：**宽口径**（该车次年在我司有新保单即算续保，含跨年断保回流）。

## 讨论

- 业务定性：探针已见全量 VIN 从 2021 ~28 万降至 2026(1-9月) ~14 万、主全从 5 万级降至 3 万级——同事"买保险变少了"的叙事有数据支撑，本卡把问题细化成「结构降档（主全→交三→单交）× 流失」两张表讲清楚。
- 与现有卡无同源（005/006 为续保页功能改造，本卡为一次性组合迁移分析），不并卡。
- 补充需求拆解：①险别变化＝主迁移矩阵顺带产出（PolicyFact 直接可查，不受两年限制）；②保额变化＝受 third_party_coverage 不可查约束，司乘保额可直接做，三者保额需源清单/VIN 级路径，探索阶段定，可能降级为固化区聚合口径对比（2026 1-9 vs 2025 同期档位分布迁移）。
- 风险：四川分支数据是否入表（owner 账号 SX 默认视角可见两省）——默认按 SX 视角（与探针一致），如需两省合并或单列在出数时声明。

### 【断言】出数执行方案（代码推理，待开工跑数验证）
